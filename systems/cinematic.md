# 电影感产品页 — cinematic product page

> 来源：offerstudio.group 全站逐屏拆解（15.5 屏，bundle 312K 已分析），
> 并用 Tempo v3 落地验证（11/11，p95 17–18ms，页高 12296px ≈ 13.7 屏）。
>
> **什么时候用这篇**：brief 里出现「高级感」「电影感」「像 Lando / 像 offerstudio 那个站」。
> 这类需求用默认 Product 流程会产出「精致的文档」——每个数字都合格，但整体是排版，不是画面。
> 那不是执行失误，是流程本身不对：中央容器 + 信息密度 + 每段一个小动效，是从「填一张信息表」出发的。
> 这篇从「造一个空间」出发。

---

## 一、先拆穿一个幻觉：工具与效果无关

offerstudio 实测（bundle 逐处核对过）：

| 项 | 实测 |
|---|---|
| 滚动库 | **没有 Lenis**（0 处） |
| WebGL | **没有 three**（0 处） |
| GSAP | 核心方法 25 处，**ScrollTrigger 只有 3 个** |
| 框架 | React（Vite 构建） |
| 字体 | **Inter**——和任何模板一样 |
| 体量 | 15.5 屏，最大字号 128px / w700 / -0.03em |
| 动画转场 | 大量是 **CSS keyframes**，不是 GSAP |

工具箱比一个典型模板还小。所以「它工具好」不成立，
「它用了什么我没用的库」也不成立——**差别在结构和意图，不在库**。

---

## 二、结构：6 个区块，2 个长场景占 57%

offerstudio 全站的滚动长度分配（13990px 实测）：

| 区块 | 滚动长度 | 形态 |
|---|---|---|
| Hero 长场景 | ~4000px（4.5 屏）| **pin**：口号定住，副句逐句浮现，光场演化 |
| 成绩过场 | ~1350px | 一屏，48px 标题 |
| Portfolio | ~1350px | 一屏，作品 |
| Team 长场景 | ~4000px（4.5 屏）| **pin**：128px 大字长驻，插画铺满 |
| Contact | ~1350px | 一屏 |
| 闭环 | ~1350px | **重复首句** |

法则：

1. **只有 6 个区块。** 不是一个「完整官网」的 10 段。每一段都有存在的理由。
2. **两个长场景占大头。** 每个场景 = pin 住一屏 + `end: '+=3500~4000'` + 一条 scrub 时间线。
   时间之内，画面自己在演化；用户只是拨时间线的拨杆。
3. **口号贯穿、结尾闭环。** 首句在结尾原样回来——用户读完全站再看到它，
   它的意思已经变了。这一下是「作品」和「页面」的分界。
4. **过场只给一屏。** 过场（数字/联系）不是主角，给多了会把节奏摊平。

Tempo v3 的对应结构（已验证）：hero pin 4000px → 信任行 → 成果 → 过程 → **能力 pin 3400px** → 定价 → 闭环。

## 三、文案：一句口号，先于一切

offerstudio 首屏：「Your website is your strongest offer.」——能印在 T 恤上。

**流程是反的**：先有这句话，15.5 屏全是它的展开；结尾把它原样放回来。
不是「列完功能再想个标题」。

口号的判据：**它是一句立场，不是一句说明。**
「一小时的录音，变成三张任务卡」是说明；「会开完了，事情才开始」是立场。
说明写的是产品做什么，立场写的是用户的世界因为什么而不同。

副句（长场景里逐句浮现的那几句）才是说明——它们轮流出现、轮流退场，
每一次都带着高亮关键词（offerstudio 用品牌蓝，Tempo 用 `#7aa0ff`）。

## 四、每个场景是一幅铺满的画，文字压在画上

这是和「排版页」最本质的差别：

| 排版页（默认 Product） | 画面页（本篇） |
|---|---|
| 白底，元素排在纸上 | 底是**环境**：光场、插画、照片铺满 |
| 留白是空的 | 空是**有东西的空间** |
| 文字自己支撑画面 | 文字是画上的标注 |
| 深色段是「对比」 | 深色是「世界的底色」 |

判据：把截图缩小到 25%，排版页变成「白底上几行字」，画面页变成「一张海报」。
**如果你的首屏缩到 25% 只剩文字，就没有完成。**

### 光场的完整实现（Tempo v3 实测，p95 17ms）

```
底层：#05070d（纯黑偏蓝。灰黑会脏）
射线层：240 条，离屏 canvas 画一次（每条 createLinearGradient，
        近端 rgba(150,190,255,.05-.15) → 远端透明，lineCap round）
粒子层：260 个，每帧画（arc），离心漂移 + 闪烁（sin 相位）
        粒子半径 0.6–3px，近大远小；出界重置回中心附近
运动：整体旋转 0.00009 rad/frame（≈120s 一圈）——
      慢到看不出在转，但停不下来；粒子层转速 ×1.35 制造视差
呼吸光晕：一个 CSS radial-gradient 圆放在中心，让光"有个源"
```

**性能红线**：射线如果每帧重画渐变，p95 直接爆到 45ms+。
必须离屏画一次，每帧只 `rotate + drawImage`。
离开视口用 IntersectionObserver 停止绘制。

### 坑：深底浅字，忘了反白就全部隐身

光场的射线和粒子都是「深底上的浅色」。重写时丢掉 `.pin{background:#05070d}`，
米白底透上来，**整层视觉等于不存在**，而控制台零报错——只能靠眼睛发现。
文字同理：场景容器必须显式 `color:#fff`，否则标题继承 body 的深色，在深底上消失。

## 五、两个 pin 时间线的写法

### Hero 长场景（4000px）

**口号的显影放在页面加载时，不放滚动时间线。**
第一印象不能等用户滚 1300px 才显完整（v3 踩过：滚动 300px 时显影只完成 22%）。

```js
// 加载：显影
gsap.set('.slogan', { opacity:0, y:46, clipPath:'inset(100% 0% 0% 0%)' });
gsap.to('.slogan', { opacity:1, y:0, clipPath:'inset(0% 0% 0% 0%)',
  duration:1.15, delay:.15, ease:'expo.out' });

// 滚动：副句轮换 + 退场（总长 1.9，映射到 4000px）
heroTl
  .to('.w1', { opacity:1, y:0, duration:.35 }, 0.05)
  .to('.w1', { opacity:0, y:-26, duration:.3 }, 0.55)   // 收走，不是叠加
  .to('.w2', { opacity:1, y:0, duration:.35 }, 0.75)
  .to('.w2', { opacity:0, y:-26, duration:.3 }, 1.25)
  .to('.hero-glow', { scale:1.5, duration:.5, ease:'power2.in' }, 1.35)
  .to('.slogan', { opacity:0, y:-40, filter:'blur(6px)', duration:.45 }, 1.45);
```

- 副句**轮流**出现/收走，不叠加——两句话同时在屏上就乱了
- 退场用 `blur(6px)` + 上移：从「清晰」走向「深处」
- 副句位置放在口号**下方**（top 63%），不要和口号同点叠放

### 能力/Team 长场景（3400px）

```js
canTl.to('.giant', { opacity:1, y:0, scale:1, duration:.8, ease:'expo.out' }, 'in')
    .to('.can-row', { opacity:1, y:0, stagger:.5, duration:.6 }, 'in+=0.5')
    .to('.can-stage', { y:-40, opacity:.25, duration:.5, ease:'power2.in' }, 'in+=2.6');
```

- 128px 大字**定住不动**，是这一幕的锚
- 条目 `stagger: 0.5`——比常规大一个数量级，因为它们要跨 3400px 慢慢出现
- 结尾整段上收淡出，把接力棒交给下一段

## 六、动作词汇：发明自己的名字

offerstudio 的 CSS keyframes 全是有语义的名字，没有一个是 `fadeUp`：

| 名字 | 定义 | 效果 |
|---|---|---|
| `textSplitLeft/Right` | `translate(±150vw)` | 文字**飞出屏幕 1.5 倍宽** |
| `maskExpand` | `scale(1)→scale(50)` | 一个圆放大 50 倍铺满 = 章节转场 |
| `heroTextSlideUp` | opacity + `translateY(60px)` + **`clip-path:inset(100% 0 0 0)`** | 三重叠加：显影而非搬运 |
| `speedLine` | `translateX(-100%) scaleX(0)→(100%) scaleX(2)` | 速度线 |

两个规律：

1. **尺度是数量级的。** 150vw、scale 50——不是「移动一点」，是「离开这个世界」。
   通用模板的位移是 18–40px，那是 UI 反馈，不是动作。
2. **一个动作叠三重属性。** 位移 + 透明度 + clip-path 同时做，两个速度差 0.1–0.2s
   产生「厚度」。只做位移是搬运，加上遮罩才是显影。

给动作起名字（`.warp`、`.split-out`、`.reveal`），这个站就有一套**自己的语言**——
下次改版时你不是在调参数，是在用这门语言写句子。

## 七、数值表（实测）

| 项 | 值 | 对比「排版页」的习惯 |
|---|---|---|
| scrub | **1.5–2.5** | 模板常用 0.8–1；长惯性 = 重 |
| stagger | **0.035–0.05** | 模板常用 0.06–0.1；小错拍更密 |
| 弹性 | `back.out(1.5)` 至少一处 | 全 power/expo 是无弹性的 |
| pin 长度 | `+=3400~4000` | 每场景给足时间 |
| 大字 | 128px / w700 / -0.03em / lh 1.04 | 字号越大字距越负，字重可以越重 |
| hero 元素数 | **4 个**（logo / 口号 / 一个提示） | 模板 hero 通常 7–9 个 |
| 场景内文字 | 压在画上，白/渐变 | 深底浅字，强调用渐变发光，不用斜体（中文合成斜体会廉价） |

## 八、四个坑（全部实测）

1. **深底浅字忘反白**——光场层、场景容器、标题都要显式设色。控制台零报错，靠眼睛发现。
2. **口号显影放进滚动时间线**——第一印象迟到 1300px。加载归加载，滚动归滚动。
3. **pin 的移动端分支漏写**——`gsap.matchMedia()` 懒执行，小屏签名动作整个消失且不报错。
   小屏必须有一个轻量替代场景。
4. **深浅过渡夹中间色**——深蓝(#05070d)和暖米(#faf9f6)之间放 `#c9cdd6` 会变成脏灰雾。
   两段式：`linear-gradient(#05070d 0 46%, var(--bg) 100%)`，先纯深，再直达。

## 九、素材：画需要真的东西

光场可以程序化，但 offerstudio 的 Team 场景（插画铺满）和 Portfolio（作品照片墙）
**是真实素材铺出来的**。程序化视觉只能顶位，撑不满 15 屏。

所以确认 brief 时必须问（已加入 SKILL.md 第五问）：**有没有真实素材**——
产品截图、照片、logo、客户标、数据。有，场景就是画；没有，先声明哪些位是占位。

## 十、验收（替代 12 项里的部分判据）

- 12 项 verify 仍要过（字号比、滚动驱动、帧耗时），其中第 4/5 项按 ≥96px 放宽
- 缩到 25% 看首屏：必须是「一张海报」，不能是「白底上几行字」
- 全页滚动长度 ≥ 12 屏；2 个 pin 场景占 ≥ 50%
- 结尾能找到首句（闭环）
- p95 ≤ 20ms（光场必须离屏，见第四节红线）
- `prefers-reduced-motion`：口号直接可见，光场静止，pin 展开
