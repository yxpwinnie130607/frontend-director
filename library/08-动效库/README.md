# 动效库 / Motion library

> 这里的每一条，都是从**真实上线站点**里逆向出来的一个具体动效 —— 附原站参数、shader 原文、
> 可运行复现、以及"抄错了会怎样"的判据。
>
> 不是灵感板，不是 Awwwards 截图。是**能直接搬进项目的代码 + 为什么这样写**。

## 为什么要有这个

`systems/` 里那十一个文件讲的是 3D loop 的**语法**，`02-可运行基线` 讲的是**版式骨架**。
两者都不回答一个具体问题：*"这个站上这个动作，是怎么做出来的？"*

Lando 的"人脸 ↔ 金属面罩"就是这样：它看起来像一个 morph，实际是一层 2D 合成 + 波浪遮罩 +
流体光标 + 一张 RT。**不知道这个结构，你只能做出一个看起来差不多的淡入淡出。**

这个库就是把这些结构一条条拆开存下来。条数够了，接到需求时不是从零发明，而是**取一条最近的，换掉贴图和参数**。

## 一条动效的目录规范

```
<effect-id>/
  README.md     逆向报告：来源、机制、参数表、逐行解释、失败判据
  index.html    可运行复现（单文件，CDN 依赖，双击就跑）
  assets/       可选。原站素材，默认不放（版权 + 体积），README 里给 URL
```

硬要求：

1. **必须能跑。** 打开 `index.html` 就是那个效果，不需要 build、不需要装包。
2. **参数必须来自原站。** 写 `1.5s / expo.inOut`，不写"比较慢的缓动"。
   README 里的参数表要能被 `grep` 到原代码位置。
3. **必须写清"简化了什么"。** 复现和原站不一样的地方要主动列出来，否则用的人会以为拿到了 1:1。
4. **必须写失败判据。** "做错了长什么样"，比"做对了长什么样"更能省时间。
5. **换资源不改代码。** 用 `?assets` 一类开关加载真素材，shader 一行不动 —— 这是逆向成功与否的自检。

## 下一批（按"可实现度 × 冲击力"排的，不是按名气）

DOM 类先做 —— 它们能被直接放进任何项目，不要求 WebGL：

| 站点 | 要拆的动作 | 技术 |
|---|---|---|
| Cuberto | 图片跟随指针揭示 + 磁吸按钮的边界回弹 | DOM / GSAP |
| Locomotive | 平滑滚动下的多层视差与速度 skew | Lenis / transform |
| Basement | 标题字母被打散后按速度重组 | canvas / DOM |
| Resn | 拖拽惯性 + 松手后的磁吸归位 | pointer + spring |
| Mercury | 分屏两侧不同步滚动，交接处的遮罩 | sticky + clip |

WebGL 类（更重，价值也更高）：

| 站点 | 要拆的动作 | 技术 |
|---|---|---|
| Lusion | 粒子在形态之间流动式重组 | GPGPU |
| Active Theory | 场景切换时的 GPU 溶解与光溢出 | shader pass |
| Ojo | 卡片在 3D 空间里翻面，背面是另一段内容 | WebGL / CSS 3D |
| Igloo | 全景房间里点热点换场景 | 全景 + 转场遮罩 |
| Apple | 滚动驱动逐帧产品拆解（sticky + 序列帧） | scroll + 序列图 |

## 怎么被用起来（给接单时的自己 / 给 AI）

1. 先看**触发**（hover / scroll / drag / pointer / 时间）—— 这是筛掉 90% 的第一刀
2. 再看**技术**（DOM / canvas / WebGL）—— 项目里没 WebGL 就别翻后三行
3. 打开那条的 `README.md` 读"参数表"和"失败判据"
4. 打开 `index.html` 看结构，整段搬走，只换资产和色
5. **不要重新发明。** 这个库存在的理由就是让你别从零写

## 和验收的关系

`verify.mjs` 的 12 项是给**页面**用的（字号比、字距、滚动驱动数）。
动效条目是**组件**，不走那套。每条自己的验收标准写在 README 末尾的「验收」一节。
